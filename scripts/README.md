## 1. 概述

### 1.1 测试对象与目的

| 项 | 内容 |
|---|---|
| 被测系统 | ChainSIP 区块链养老保险平台（后端 + 前端 + 链上合约） |
| 后端 | Spring Boot 2.7.18 / JDK 8 / MyBatis-Plus 3.5.3.1 / MySQL 8 |
| 前端 | Vue 3 + Vite + Element Plus + Pinia + Vue Router + axios |
| 链 | FISCO BCOS 2.11.1，5 节点（4 sealer + 1 observer）、PBFT，groupId=1 |
| 合约 | `ChainSIP`（账户/资金/监管）、`ChainSIPTransfer`（转移状态机），Solidity 0.6.10 |

测试目的：验证平台在 **界面呈现、交互易用性、安全边界、各层集成** 四个方面符合需求与安全约束，重点是「**链下决定你能看见什么，链上决定你能做成什么**」的双层判权是否真正落地。

### 1.2 术语

| 术语 | 含义 |
|---|---|
| 链上 / 链下 | 链上 = 合约状态（权威账本与权限）；链下 = 后端 REST / 前端界面（认证与索引） |
| `msg.sender` | 合约按交易签名地址判权；链下角色写得对，链上不认照样回滚 |
| 链下角色 | 平台登记角色（`role`），只决定界面可见性与第一道门禁 |
| 链上角色 | 合约 `roleOf` 返回的角色，最终裁决依据 |
| `@RequireRole` | 后端拦截器（`JwtAuthInterceptor`）做的链下第一道角色门禁 |
| 资金守恒 | 三条恒等式：`deposited == sponsorPoolTotal + paid`、`paid == personalFund + cityPoolTotal + escrowedPersonal + escrowedOverall`、`cityPoolTotal == overallRights` |

### 1.3 角色与权限矩阵

| 角色 | 代码 | 说明 | 主要页面 / 能力 |
|---|---|---|---|
| 平台管理员 | `ADMIN` | 平台运营，链上为合约部署者 | 机构管理、职工建档、政策参数、机构私钥、注资、合约调试台、链上索引 |
| 社保局 | `BUREAU` | 经办，管理本局辖区 | 缴费单位账号、辖区总览、养老金支出、转移办理（接收/放行） |
| 缴费单位 | `SPONSOR` | 企业，为职工缴费 | 职工账号、职工管理、缴费管理（建档/调薪/缴费/减员/接续） |
| 监管 | `REGULATOR` | **纯只读** | 监管大屏、链浏览器、链上索引 |
| 职工 | `EMPLOYEE` | **不是角色**，是「有参保档案」的状态 | 我的社保账户、关系转移（申请/接续）、领取养老金 |

> 判定口径：`EMPLOYEE` 在链上无角色（`roleOf` 返回空），界面据此显示「未查询到」而非伪造角色值。

## 2. 测试环境与前置条件

| 项 | 值 |
|---|---|
| 后端 | `http://127.0.0.1:8080`（REST + Swagger `/swagger-ui/index.html`） |
| 前端 | `http://127.0.0.1:5173`（Vite dev，代理 `/api` → 8080） |
| 数据库 | MySQL 8，库 `chainsip`，`127.0.0.1:3306` |
| 链 | FISCO BCOS 2.x，channel 端口 `20200`，SDK 配置 `./sdk/config.toml` |
| 引导账号 | `admin / ChangeMe_123456`（`DataSeeder` 自动创建） |
| 健康检查 | `GET /api/public/health`（免登录，返回 `status=UP/DEGRADED` 与 `warnings`） |

**前置条件（逐项自检）：**

1. 后端已启动，`GET /api/public/health` 返回 `status=UP`（数据库与链网关均就绪）。
2. MySQL 8 已建库，`schema.sql` 已在启动时幂等执行。
3. 两个合约已部署且地址已写入 `application.yml`（`chainsip.chain.contracts.core / transfer`），否则链相关接口返回 503 + `code=2001`。
4. 前端已启动（`npm run dev`），代理 `/api` 指向后端。
5. 本机 Python 可执行（`python`）用于跑自动化脚本。

> **关于 JWT 密钥（D-02）**：后端在**非 dev 环境**启动时若仍使用仓库默认 JWT 密钥会直接拒绝启动。本地开发/测试请以 `--spring.profiles.active=dev` 启动，或在 `CHAINSIP_JWT_SECRET` 环境变量注入自己的密钥。

## 5. 安全测试

### 5.1 安全模型回顾

ChainSIP 采用 **双层判权**：

1. **链下第一道门**：`JwtAuthInterceptor` 解析 JWT 放入 `AuthContext`，按 `@RequireRole` 校验角色（`401` 未登录 / `403` 无权限）。
2. **链上最终裁决**：合约按交易签名地址 `msg.sender` 判权，链下角色与链上不一致时交易回滚。

此外：密码 PBKDF2-HMAC-SHA256（12 万次迭代）存储；机构私钥 AES-256-GCM 加密落库；JWT 用 HS256。

### 5.2 认证与授权测试

| 编号 | 用例 | 步骤 | 预期结果 |
|---|---|---|---|
| SEC-01 | 登录凭证缺失 | 无 `Authorization` 头访问受保护接口 | HTTP 401，`code=401`，提示「缺少登录凭证」 |
| SEC-02 | 登录凭证格式错误 | 携带非 `Bearer ` 前缀的 token | HTTP 401 |
| SEC-03 | JWT 伪造 | 用错误密钥/篡改 payload 的 token | HTTP 401「登录凭证无效」，不通过 |
| SEC-04 | JWT 过期 | 使用过期 token（`expire-minutes` 后） | HTTP 401「登录状态已过期，请重新登录」 |
| SEC-05 | 登录失败锁定 | 连续错误密码登录 | 不返回额外敏感信息，仅「用户名或密码错误」；失败不泄漏账号是否存在 |
| SEC-06 | 改密码校验原密码 | `POST /api/auth/password` 传错原密码 | HTTP 400「原密码不正确」，密码不被修改 |
| SEC-07 | 弱新密码拦截 | 新密码 < 6 位 | HTTP 400「新密码至少 6 位」 |
| SEC-08 | 修改账号信息校验 | `POST /api/auth/profile` 传错当前密码 | HTTP 400「当前密码不正确」；只能改自己（账号取登录态） |
| SEC-09 | 登录日志可追溯 | 登录接口记录 | 后端记录客户端 IP 与 User-Agent（`clientIp`），用于审计 |

### 5.3 越权 / 角色门禁测试

| 编号 | 用例 | 步骤 | 预期结果 |
|---|---|---|---|
| SEC-10 | 角色越权（链下） | `SPONSOR` 调用 ADMIN 接口（如 `/admin/sponsors`） | HTTP 403「当前角色 SPONSOR 无权访问，需要 [ADMIN]」 |
| SEC-11 | 角色越权（只读监管） | `REGULATOR` 调用写接口（如开机构） | HTTP 403；监管端无任何写入口 |
| SEC-12 | 辖区越界（数据面） | `BUREAU` 查询非本局辖区的职工参保记录 | HTTP 403（后端按本局服务城市守界） |
| SEC-13 | 单位归属校验 | `BUREAU` 给不属于本局的缴费单位注资 | HTTP 403「该缴费单位不属于本社保局」 |
| SEC-14 | 越权直达前端路由 | 见 UI-10 | 前端拦截并跳回 dashboard |
| SEC-15 | 越权接口直达（绕过前端） | 用正确 JWT 但错误角色 curl 受保护接口 | HTTP 403，前端拦不住不代表后端放行 |

### 5.4 密码与密钥安全测试

| 编号 | 用例 | 步骤 | 预期结果 |
|---|---|---|---|
| SEC-16 | 密码不明文存储 | 查库 `cs_account` 表密码字段 | 存储为 PBKDF2 派生值（盐+哈希），非明文 |
| SEC-17 | 机构私钥加密落库 | 查 `cs_institution_key` 表私钥字段 | 为 AES-256-GCM 密文，非明文十六进制 |
| SEC-18 | 敏感信息不回显 | 调用 `/auth/me`、机构私钥、健康检查 | 不返回 JWT secret、主密钥、私钥明文内容 |
| SEC-19 | 默认密钥体检 | 观察 `/api/public/health` 的 `warnings` | 若仍用仓库默认 JWT/主密钥，`warnings` 给出「生产必须替换」提醒 |
| SEC-20 | 联调代签接口 | `POST /api/auth/demo/sign` | `allow-demo-sign=true` 时可用；置 `false` 后返回 403「联调辅助接口已关闭」 |

### 5.5 传输与数据安全测试

| 编号 | 用例 | 步骤 | 预期结果 |
|---|---|---|---|
| SEC-21 | CORS 白名单 | 非同源前端跨域请求 | CORS 配置 `allowedOriginPatterns("*")` 仅供本地调试；生产应收紧到具体域名 |

## 6. 集成测试

### 6.1 测试目标

验证「**后端 ↔ 数据库 ↔ 链上合约 ↔ 前端**」全链路协同正确，尤其是资金守恒、跨城市转移状态机、养老金支出、政策快照等需要多组件配合的核心业务。

### 6.2 集成层次

```
前端 (Vue 3) ──axios──▶ 后端 (Spring Boot) ──MyBatis-Plus──▶ MySQL 8
                              │
                              └──FISCO Java SDK──▶ FISCO BCOS 链（合约）
```

- **认证/账号/索引** 依赖后端 + MySQL。
- **所有上链业务**（建档、缴费、转移、退休、发放）依赖后端 + 链，链路失败必须给出 503 + 排查提示而非静默。

> 幂等仅指「不依赖已有演示数据、可重复跑」，**并非无副作用**：每次运行都会新增社保局、缴费单位、职工、政策版本与链上交易，测试数据会持续累积（D-11）。用于演示库前请评估是否清理，或为测试账号加统一前缀以便批量删除。
